# PySide6 Spectra Analysis App

Standalone desktop app for `.dat` spectra maps with:
- root-folder scan and process-folder selection,
- multiple DAT import and cached dataset switching,
- multiple named graphs per DAT, with separate ranges, gate, titles and styles,
- heatmap + linked gate spectrum (click heatmap or use the plot navigation bar to update the single current gate),
- peak finding on selected spectrum,
- manual per-peak editing by clicking on the spectrum (left click add, right click remove),
- independent detection and fit ranges (`xmin/xmax`), with an explicit **Use Current X Range** copy action,
- optional Savitzky-Golay smoothing for detect/fit input,
- multi-peak fitting with Lorentzian or Gaussian models,
- explicit **Detect Then Fit Current Gate** preparation for Find Peaks seeds (edited seeds are preserved),
- separate **Export Current Gate CSV** and **Export All Results CSV** actions; all-results output preserves batch rows and failures,
- current spectrum CSV export with raw and analysis columns,
- batch auto-fit across all gates in one DAT with CSV export.
- **Workspace** is the daily document area for Workbooks, XY comparisons and formal heatmap pages. **Analyze** opens contextual curve tools for XY graphs, or the shared full-size DAT Analysis view with linked heatmap, Gate spectrum, navigation toolbar, peak detection and fits; **Back to Workspace** returns to the source document. A formal page uses the dataset's current view; its default paper width is **91.5 mm** (exactly 91.5/25.4 inches), height **3.45 inches**, with an explicit **2.90 × 2.80 inch heatmap frame**, **10 pt numbers**, **12 pt text**, **Arial**, and **300 DPI** for the heatmap (**1081 × 1035 PNG pixels**). Frame width and height are independent of the paper aspect lock. When measured labels or colorbars need more space, only the outer page grows, retaining the exact chosen frame and font sizes. Growth follows the paper aspect lock, is limited to the supported 40 inch page dimensions, and is reflected in the controls, preview, exports and saved graph settings. Pages that already fit stay unchanged; explicit Auto-fit remains available. Invalid or overlapping tick choices still require correction before export. Analysis and Plot share **Display: Fit / 100% / 150% / 200%**; 100% means 96 logical pixels per inch and larger Analysis contents scroll. Display scale changes neither export dimensions nor stored point sizes. Horizontal and vertical major ticks each offer **Auto / By increment / By count**. Count includes both endpoints on linear coordinate axes (2–100); **Count between major ticks** sets 0–20 minors per interval. Manual increments/counts are preserved; crowded choices require more paper or fewer ticks before export. The filename is optional **Add text** inside the frame, where it can be moved and saved; a fresh import has no filename header. The top colorbar defaults to a short **0.70 in** rectangle aligned with the frame's right edge and the signal on its left. Alignment, signal position, bar height, gap above the frame, minimum space between bars, and optional under/over triangles are adjustable. Labels keep their chosen fonts; measured space expands bars or stacks long/regional headers when needed. The status reports cells below/above the scale even with rectangular ends.
- **Export SVG / PNG** saves the current formal page in the project folder for project-owned datasets, or beside an ordinary imported DAT, with the next unused `_export01`, `_export02`, etc. suffix. Preview and exports consume the same SVG bytes. SVG embeds one heatmap raster and retains editable text, axes, ticks, continuous vector colorbars, arrows and optional selected peak labels. Fonts are named rather than outlined; another computer can substitute unavailable fonts. PNG records source provenance, view, processing and formal-page settings in its metadata.
- **Title presets** offers **Manual**, **Current group**, and your saved presets. Manual accepts any literal title, including blank. Current group uses `E={voltage}V {field}T {valley}` with `85=K;175=Kp`; these angle labels belong only to that preset. For example, `$YZD320$~$pa$~$8T3.6KRef0.2sx10$~$680nmc$~$R1_85deg$~$0.95TG-BG=18$_rep01_001_avg13_DR_R_External_d2E_Regrid.dat` produces `E=18V 8T K` (voltage is the right-hand value `18`, not the coefficient `0.95`). Edit the format to choose fields/order, use **Insert field**, change the simple angle map, then enter a name and **Save preset**. Allowed fields are `{voltage}`, `{field}`, `{angle}`, `{valley}`, `{temperature}`, and `{sample}`; units are literal text, and `{{` / `}}` insert braces. Only clear, unambiguous filename values are used; missing fields clear the generated title and show a message. No expressions, attribute/index lookups, or format codes are supported.
- Selecting or editing a template sets the default for new files and survives restart. Editing **Plot title** makes a per-DAT override, including an intentional blank; **Apply template** regenerates that DAT's title. Previously saved DAT files recall their own complete template snapshot and override without replacing the default for new files. Named presets are stored locally; copying DAT + JSON also carries custom templates to another computer without installing the preset there.
- **Fix annotations** (on by default) retains Y-axis name/unit and manual Colorbar label as defaults for new files. For backward compatibility, it also retains manual titles in **Manual** mode. In template mode, each new DAT gets a fresh generated title; manual overrides never become global title defaults. Previously opened DAT files restore their own saved annotations first. **Auto from data** colorbar labels recognize explicit Signal metadata and conservative basename tokens such as `PL730nm` and `DR_R`; unknown sources use `Signal (arb. units)`. Reflection labels default to `ΔR/R₀`, including applied derivatives; manual labels retain their literal text when saved or restored. Short reflection, derivative and PL presets remain editable; choosing a label does not transform the data.
- **Colormap** prioritizes `jet`, `RdBu_r` and `RdBu_r_0.6` with gradient previews. Fresh recognized PL chooses `jet`, reflection chooses `RdBu_r`, and saved or manually chosen palettes take precedence. `RdBu_r_0.6` uses the exact bundled colors and retains the canonical `RdBu_r_p0p6` name in sidecars and formats. Changing palette preserves numeric color limits and mapping.
- **Color Scale** states the current Auto, partial manual or Manual mode and its visible-data scope. Automatic limits use the current processed heatmap's 0.5/99.5 percentiles. Editing a color bound locks only that endpoint; the legacy **Fix** boxes remain available. **Auto / recalculate colors** unlocks both endpoints and recomputes colors for the current visible view. Independent regional scales disable the global bounds. Analysis and Plot report below/above-scale counts and percentages of visible valid cells, including when colorbar triangles are hidden.
- **Recall plots** stores a readable v6 sidecar beside each ordinary imported DAT: `sample.dat.plot.json`. It preserves every named graph and the selected graph, with separate ranges, color limits, palette, mapping, axis/signal text, title preset/override, selected Gate, Fix controls, formal dimensions/fonts/layout, custom colorbar ticks, and manual text/arrows. Processing and source-axis interpretation are shared. Switching/reloading, closing, exporting and applying formats save the collection. Copy the DAT and JSON together to carry the setup. DAT contents remain unchanged; changed-source or invalid sidecars are skipped with a message. Version 1–3 recipes remain readable as **Graph 1**, with defaults for their missing fields. Sidecars contain plot recipes; Save Project embeds scientific arrays and completed peak/fit results in the portable project file.

Gate navigation is committed from the plot bar: arrow/index stepping is immediate, while typed gate values are applied on Enter or focus loss. The visible X range controls detection and can be copied deliberately into the independent fit range; later zooming does not change fit bounds. CSV seed selection never falls back to peak detection when the selected CSV has no seeds.

The Analysis workbench fits Lorentzian (HWHM gamma), Gaussian (sigma), or true Voigt components (independent sigma and gamma). Initial amplitudes are signed heights above the baseline; widths and center bounds use physical X units. **Edit seeds and parameters…** allows continuous positions, explicit peak/dip kind, acceptance, amplitude, width, gamma, fixed centers and optional center bounds. Seed or input changes retire affected fits.

## Install on Windows

Download `SpectraAnalyzer-VERSION-Setup.exe` from
[GitHub Releases](https://github.com/ylylyl98/Spectra_Analyzer/releases/latest)
and run it. The installer includes Python and all application dependencies;
Windows 10/11 x64 PCs need no separate Python setup or source checkout.
Open **Spectra Analyzer (Standalone)** from the desktop or Start Menu. Installation
is per user and does not require administrator access. Projects and application
preferences are preserved during upgrades and uninstall.

Use **Help → Check for Updates…** to check the public release channel. An available
update is downloaded and verified before the app offers to close and launch the
installer. Save or discard pending work through the normal close prompt. Startup
does not download or install updates automatically.

The portable ZIP is also available: extract the entire archive and launch
`SpectraAnalyzer.exe`, keeping its `_internal-VERSION` folder beside it.
See [Windows packaging](tools/windows/README-Standalone.md) for build and validation
instructions.

## Run from source

For development or other platforms, create the Python environment first:

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

On Windows, install the source checkout's desktop and Start Menu entry once from
PowerShell:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\windows\Install-Launcher.ps1
```

Open **Spectra Analyzer** from the desktop or Start Menu. To keep it on the taskbar,
right-click that shortcut and choose **Pin to taskbar** (on Windows 11, use **Show
more options** if needed), or right-click the running app's taskbar icon and pin it.
The entry targets `%LOCALAPPDATA%\Programs\SpectraAnalyzer\SpectraAnalyzer.exe`, a
GUI launcher with an embedded multi-resolution icon and a persistent Windows app
identity shared with the Qt window. Startup does not download or update anything.

The launcher uses this checkout's `run_qt.py` and `.venv\Scripts\pythonw.exe`;
keep both in place. After moving the checkout, rerun the setup script from its new
location. This preserves the installed launcher path, taskbar identity and existing
app settings. Startup failures show a message; Python diagnostics are saved in
`%LOCALAPPDATA%\Programs\SpectraAnalyzer\logs\startup.log`. A single `.spectra` or
`.spextra` filename can also be passed to `SpectraAnalyzer.exe`, including paths
with spaces or Unicode characters. The old update-on-start and local BAT launchers
have been retired.

For development or other platforms:

```bash
python run_qt.py
```

## Import and switch datasets

Use **Import data…** in File (**Ctrl+O**), Project or Data Source, or drop numeric DAT, TXT, CSV, TSV or XY files together. Content is detected automatically and full tables open directly as one Workbook per file in **Workspace**, with no preview or confirmation. New tables use the first column as X and **every remaining column as Y**; all rows and columns are retained. **Import with options…** in File or Project → Actions optionally opens the preview for type correction, X/Y roles, grouping and comparison. **Browse…** discovers folders, and **Folder files (inventory)** lists the selected folder's files; **Load Selected File** and double-click use the same automatic import.

**Imported datasets** contains the source files opened in this app session, with a count of the visible and total datasets while searching. Search by filename or any part of the folder path, ignoring case; clear the search to restore the full list in import order. Filtering keeps the active plot and results open, even when its row is hidden. Select a visible item with the mouse or keyboard to restore its cached plot, Gate, processing controls, peaks, completed fits, analysis summary, and CSV seeds. Selecting or importing an already imported path reuses that dataset and preserves its results. Files with the same name in different directories remain separate datasets; their labels show the shortest distinguishing trailing folder path, and tooltips show the complete source path. **Folder files (inventory)** remains the browser for files available to import.

Use **Rows** above the dataset list to show **4–12 rows** (8 by default); the preference survives restart. Format and batch-export target selectors use the same filename/folder labels and complete-path tooltips.

The **Graph name** selector below the dataset list is available in the Properties dock for Analysis and heatmaps. **Graphs → New Graph…** clones the current graph's visual settings and selects the new graph. Each graph keeps its own ranges and Fix locks, color regions and mapping, gate, titles, page/style and annotations. Ordinary source graphs share DAT data and processing. Associated Analysis Graphs own independent inputs, candidates, seeds and fits. Graph names accept Unicode, are trimmed, and must be nonempty and unique within the DAT. **Rename Graph…** keeps the graph identity; **Remove Graph…** removes its visual settings and history, selects a neighboring graph, and retains at least one graph. Finish or correct pending editors before switching. Graph lifecycle controls pause during background or batch work.

The **Project** tree stays on the left across Analysis, Workbooks and graphs. Drag its divider to resize it; **View → Project tree** (Ctrl+Shift+P) hides or restores its previous width. The header provides **Import** and **Actions**, including New comparison, Compare selected data and Merge Workbooks. Double-click or press Enter to open an item. Heatmaps are listed here even when their details are closed.

The right **Properties** dock remains in place when switching between Workbooks, XY comparisons, heatmaps and an empty Workspace. Its content follows the active document: Workbook information, the graph's own curve inspector, DAT controls, or an empty-state hint. **View → Properties** or the dock close button changes visibility until you show it again. The top command row also keeps a stable footprint; page/frame dimensions, export pixels and format settings are in Properties. Activating a document preserves the Project width, document rectangles and preview zoom. Panel widths and visibility are local to the current session and do not change project data.

**Graph name** identifies a heatmap in Project and its window; **Plot title**, **Y-axis label** and **Colorbar label** annotate its image. **Auto from data** supplies the colorbar label from existing metadata. Typing keeps the last successful paper visible and commits on Enter or focus-out; selecting a preset or Auto commits once. Save, export, close and document switches flush the latest text. Export prepares fresh bytes when necessary, and editing gestures stay disabled while the displayed paper is stale. Labels do not transform source data. Long annotations retain the fixed physical frame and fonts while the outer page grows as needed.

**Workspace** opens documents as freely movable, resizable, overlapping windows, labeled with their DAT and graph names. **View → Open Graph** opens or reopens the selected graph; new windows start at staggered positions. **View → Cascade Graphs** and **Tile Graphs** arrange all open windows once, after which they remain freely movable. **Tabbed View** groups them as tabs; **Free Windows** restores their normal rectangles. Native title bars support moving, resizing, maximizing/restoring and closing. There is no fixed window-count or column limit. Each graph retains its own preview, display zoom and editors. Clicking a graph selects its owner before editing or exporting; the Properties content and heatmap commands follow that selection. **Analyze** on a heatmap command bar opens its DAT in the shared Analysis view.

Use the heatmap **Analyze** button, **Analysis → Analyze**, or the Project context menu to create an associated **Analysis Graph** automatically. Later entry reuses that graph; clicking its Project item restores the shared Analysis editor without opening another MDI window. Original/Processed Sheet entry binds that exact input role. **Duplicate analysis** creates an independent version. **Back to Workspace**, **Source graph**, **Original data**, and **Results table** provide explicit navigation. Invalid drafts and busy operations retain their navigation guards.

The Analysis header identifies its bound input version, source graph, current Gate and display scope. **Use input** explicitly captures Original or Processed values and retires prior results. **All Gates** analyzes every Gate of that full bound input; a sparse source graph keeps only its selected display rows. The auxiliary linecut can inspect every bound Gate. Detection smoothing and derivatives never replace the input matrix.

**Find candidates** stores a loose pool. Choose Loose, Balanced, Strict or Custom and **Apply filter** to accept seeds without destroying rejected candidates; filter settings include prominence, noise strength, physical width/distance and an optional count limit. The current-Gate summary and **Edit seeds and parameters…** support manual corrections. **Fit seeds** is optional. Empty, no-seed, fitted and failed Gates remain distinct, and cancellation preserves the previous completed result.

**Save Project** retains the Analysis input, loose candidate pools, filter settings, manual/accepted seeds, fits, per-Gate outcomes, current Gate, scope, styles and source links. Reopen an Analysis Graph to continue without recomputing. Export is independent: saving progress does not require an image or result export. Earlier projects remain readable.

**View → Close Document View**, or a document's close button, closes only its view; heatmaps, Workbooks and comparisons remain available in the Project tree. Reopening restores the previous position and size. Closing the active view selects another open document when available; closing the last view leaves an empty document area and a context hint in the stable command row. **Remove Graph…** deletes the heatmap graph's saved settings. **Save Project** preserves free/tabbed mode, open and closed views, normal rectangles, active document and stacking order. All-closed workspaces reopen closed. Saved windows outside the current work area are moved so their title bars remain reachable. Preview caches and display zoom remain local to the current session.

Native projects use schema v8 to preserve heatmap graphs, Workbooks, current-result Sheets, detached snapshots, XY comparisons and validated plain-JSON document layout. Older v1–v7 projects remain readable with their grouped ownership and layout; v1 restores its original view as **Graph 1**, and v1/v2 initialize in Free Windows mode. A missing legacy layout initializes the default view, while an explicit empty layout keeps all views closed. Older application versions cannot read newly saved v8 projects. Edit history remains chronological per DAT: Undo/Redo names and selects the graph that owns a visual edit; peak edits remain shared. Switching graphs adds no history entry. Format target selectors display each DAT and its active graph and apply to that graph. Batch export lists every named heatmap graph under its DAT and exports the graphs explicitly checked. Figure export suggestions include the graph name; additional heatmaps have a stable identity suffix to distinguish names that sanitize to the same filename. Separate frozen heatmap comparison windows retain captured graph names, IDs, settings and final bytes; live XY comparisons retain Sheet references.

Each import prepares new files in the background and publishes after the worker is idle. Valid files retain request order; ordinary import opens their Workbooks with the first valid or reused source active at **Original**. Importing does not switch to Analysis or create a heatmap. Valid files are imported even if some fail; the failures are reported with their paths and reasons. If every file fails, the current dataset, plot, and results remain available. During import, dataset switching, new imports, processing, and analysis are paused; Gate navigation, plot ranges, colormap, and annotation editing remain available. **Cancel operation** discards every new dataset from the pending batch and immediately restores those controls while preserving the current dataset and its latest view edits.

CSV drops are ordinary numeric data. Use the explicit **Load Seeds CSV** command to load peak seeds for the active dataset. Native projects must be dropped separately from numeric data.

**File → Save Project** (**Ctrl+S**) saves the workspace in a portable **`.spectra`** file. Previously created `.spextra` files remain readable, and saving an opened legacy project keeps its existing filename. **Save Project As…** uses **Ctrl+Shift+S**, **Open Project…** uses **Ctrl+Shift+O**, and **New Project** uses **Ctrl+N**. The project embeds imported and processed arrays, dataset order and the active dataset, processing and pending controls, peaks and labels, completed fits and CSV export rows, CSV seeds, summaries, annotations, titles, ranges and formal plot settings. Reopening uses those embedded results even when the original DAT and seeds CSV files have moved; it does not rerun processing or fitting. The current project filename appears in the window title.

**File → Recent Projects** keeps the last **10 successfully opened or saved projects**. Labels show the filename and parent folder; hover for the complete path. **Clear Recent Projects** clears this local history. You can also drop one `.spectra` or legacy `.spextra` file into the window, or launch with `python run_qt.py "C:\path\experiment.spectra"`. Open is available when current work has finished and uses the same unsaved-changes prompt for each route. Drop projects separately from DAT/CSV files.

A **`*` in the window title** marks unsaved project changes, including pending scientific/page edits, results, Gate, plot ranges, the active dataset and graph-window layout. Opening/closing, moving/resizing and arranging graph windows are saved project changes. Save clears it; reverting an edit to the saved content clears it too. Search, formal-page preview zoom, sidebar selection and list sizing are local viewing preferences. New empty projects start clean; importing data starts an unsaved project.

New, Open and Close offer **Save / Discard / Cancel** before discarding changes. Cancel is the default; a canceled or failed Save keeps the workspace available. Project commands wait until background/import/batch work completes or is canceled. Closing first cancels outstanding operations. Pending numeric and annotation edits are committed before saving. Undo history, background jobs, separate frozen heatmap comparison windows and global preferences are not stored in projects. Live XY comparison graphs are stored with their workbooks and curves.

Ordinary DAT imports keep their `.dat.plot.json` sidecars until saved into a project. Saving or reopening a project gives its datasets project ownership and stops sidecar writes. Those datasets retain the saved X-axis interpretation; import the original DAT into a new project to reinterpret its source axis. Processing and fitting remain available. Figure, CSV and comparison exports default to the project folder; source labels keep the original DAT path as provenance.

DATs imported into an existing saved project immediately use project ownership and export to its folder. Right-click an imported dataset to **Copy Source Path**, **Open Source Folder**, **Open Export Folder**, or **Remove from Project**, without switching the viewer. Removal asks for confirmation, discards that dataset's stored analysis, Sheet and dependent curves, and leaves the original DAT unchanged. Removal is unavailable while import, analysis or batch work is running. Removing the active dataset selects its next neighbor, then its previous neighbor; removing the last DAT preserves any remaining ordinary workbooks and XY comparisons. If no other content remains, Save preserves an empty project. Separate frozen heatmap comparison windows remain available.

## Export a figure

While **Plot** is active, its sidebar includes the same **Annotations** and **View Range** editors used in Analysis: plot title, title presets, Y-axis name/unit, automatic or manual Colorbar label, axis interpretation and source X/Y bounds. Dataset recall and automatic titles use the same bindings in both modes. Double-click the displayed title or a manual note to focus its text editor; double-click an axis label, tick label, frame line or colorbar to reveal the corresponding properties. Exchanged axes map back to the original source labels and ranges, and a regional colorbar selects its own bar. Preview zoom changes only the displayed size.

**Copy SVG** and **Edit → Copy Graph as SVG** prepare a fresh, validated formal page, then place only its hybrid SVG on the system clipboard—the same bytes as **Export SVG**, with the embedded heatmap at the selected **Heatmap DPI** and editable SVG text and axes. Pending numeric edits are committed before capture. Invalid page settings leave the clipboard intact and show an error. Editing outlines and handles are excluded. **File → Import data…** uses **Ctrl+O**; **Copy SVG** uses **Ctrl+Alt+J**, with **Ctrl+C** also available when the formal canvas has focus. **View → Rescale Graph** uses **Ctrl+R** on either graph canvas and respects fixed bounds. **Escape** on a graph cancels pending label/peak drags and selection without committing a move. Text editors retain native copy and editing keys.

**Edit → Undo / Redo** shows the next operation for the current DAT. On either graph canvas, use **Ctrl+Z** and **Ctrl+Y** (or **Ctrl+Shift+Z**); focused text editors keep their native undo keys, and the explicit Edit menu still operates on the dataset. History covers committed titles/axis/signal labels, formal presentation and annotation edits, ranges and Fix locks, color styles, selective format application, and manual peak add/remove/move/clear, label changes, circle and lasso deletion. One drag or committed label edit is one operation. Each imported DAT keeps up to **100 operations in memory**; a new edit clears that DAT's redo stack. Switching DATs commits pending edits to their original owner. Navigation, display zoom, rendering and copying graphs do not add operations. Undo/redo updates the current graph and writes a sidecar for ordinary DAT imports; Save Project persists edits for project-owned datasets. Visual undo preserves later fits, analysis controls, processing choices and Gate selection. Seed changes invalidate fits and fit-export rows only for affected gates; undo restores seeds without resurrecting old fits. Source reread or applied data transformation clears incompatible history, and undo/redo waits until background work finishes. History is not saved between app launches.

Open a DAT heatmap in **Workspace** and edit its complete **Properties → View → Color Scale** controls there: **Global / 2 regions / 3 regions**, palette, **Linear / Log / SymLog / Zero-centered** mapping, threshold, color bounds and locks, region boundaries, and **Auto / recalculate colors**. Double-click a colorbar to reveal these controls and its tick/appearance editor. The same controls follow ordinary source graphs; Analysis uses its explicit **Edit source format** link. Mapping affects display without transforming scientific data or recalculating fits. Log masks nonpositive cells and reports their count; its limits must be positive. Zero-centered limits must straddle zero. Regional 2/3 modes share the palette and mapping with independent region limits.

Plot supports horizontal/vertical exchange, flips, axis visibility, border/tick controls and top colorbar layout. Scientific labels use **arb. units**. Legacy manual labels ending in `a.u.` display as `arb. units` while their editable and saved formulas remain literal. **Show signal unit** is on by default; disabling it hides recognized trailing unit text in both heatmaps and preserves the literal saved signal title. **Custom three ticks** accepts low/middle/high values and optional labels separated by `|`, for `global` or each `region-1`/`region-2`/`region-3` bar. Values must fit the chosen bar's limits. Layout failures and invalid edits disable current export until corrected; fonts are never silently reduced to fit.

The upper Analysis heatmap is the formal result: its preview, SVG, PNG and clipboard export use the same renderer and bytes. Source titles, fonts, dimensions, axes, colors, normalization and regions remain linked continuously; **Edit source format** opens that source graph. Detected/manual and fitted-center scatter layers have independent visibility and styles. The lower Gate linecut and editor controls are auxiliary and excluded from heatmap export. Wheel zoom, drag pan and double-click Fit change only the displayed preview.

Use **Save format…** to store a named format locally. **Load for current** recalls it for the current DAT; **Apply to datasets…** opens a separate checkbox target selector with Select all/Clear and each target's concrete changes. It copies page/style/fonts/DPI, axis and colorbar layout, and palette. By default it retains each target's mapping, axis/global/regional ranges, region boundaries, title, text, custom ticks, manual annotations and selected peaks. **Copy color mapping** and **Copy color limits** are separate options, both initially unchecked. Invalid targets are reported individually, while valid targets are applied, with sidecars saved for ordinary DAT imports; Save Project persists project-owned targets. Applying formats preserves raw/processed data and completed fits.

**Batch export…** selects named graphs within or across imported DATs in a checkbox tree. Only the current graph starts checked; DAT checkboxes select all their graphs, and **Select all** / **Clear** act on every graph. Export SVG, PNG or both in the project folder for project-owned datasets, beside ordinary DAT imports, or in one existing common output folder. Jobs freeze each selected graph's ranges, title and style at the request, run serially with progress in graphs, and keep the current DAT/graph selection and scientific controls. Invalid current visual drafts fail only their owning graph; other valid selections can export. Ordinary-DAT sidecars save the live graph collection once per DAT, keeping its active graph; sidecar save failures appear in Results without suppressing valid exports. **Cancel batch** cancels remaining graphs between SVG/PNG pairs; already written files remain. **Results…** identifies each DAT and graph with per-format paths, errors, pending and canceled outcomes. Exports always choose an unused number and never overwrite earlier files.

Use **Add text…** for Unicode labels such as `9T σ⁺`, or **Add arrow…** with an optional number. Select an annotation in the list or on the paper, drag its text/tail or arrow-head handle, edit its text/coordinates/coordinate spaces/font role/visibility, and apply the edit. Coordinates are axes fractions or original data units, so exchange, flips and preview zoom preserve their meaning. Arrow keys nudge the selected text/tail (Shift for larger steps); Delete removes the selected annotation on the paper. Editing outlines and handles never enter SVG/PNG output. Each graph retains its own annotations: ordinary DAT imports use their v6 sidecars, and project-owned datasets use Save Project.

Heatmap image export is available in Workspace and the Analysis workbench through **Export SVG**, **Export PNG**, and **Copy SVG**. Batch export remains available from Workspace. Export dimensions come from the source format; preview zoom does not alter output size. Invalid formatting prevents export until corrected.

## Read tables and compare XY curves

Every Workspace graph exposes **Analyze**: heatmaps use the DAT tools above, and **XY graphs** in **Line**, **Scatter**, or **Line + Symbol** style use curve tools. An XY graph has its own **Analyze** command in the top command row, **Analysis → Analyze**, and Project’s graph context menu. It opens **Curve analysis** in the right Properties inspector and keeps the large graph canvas in Workspace. Select exactly **one** curve in the Curves list; zero or multiple selections display a prompt. Pending valid graph edits are committed before analysis; invalid drafts stay in place for correction. CSV Workbooks and Sheets remain data sources: first plot their columns, then analyze the selected graph curve. The same tools accept curves sourced from live DAT Sheets or detached snapshots.

**Highlight selection** in Curves is on by default: click a curve or its list row to emphasize it in its original color and fade other visible curves and legend entries. Up/Down browses the list; Ctrl/Shift selects several curves. Esc while the canvas or list has focus, or an empty canvas click, clears the selection. Turn off Highlight selection to view original styles while retaining selection. Checkboxes still control visibility; hidden curves stay hidden, and pan/zoom clicks do not select curves. This preview effect preserves source data, stored styles, zoom and SVG/PNG/clipboard exports. Browsing also retains completed analysis, seeds and fits for their captured source; return to that curve to use its results, or explicitly choose **Find candidates** to start analysis for a different selected curve. Fit is disabled while the selection differs from the retained source.

Use **Find candidates**, adjust the Loose, Balanced, Strict or Custom filter, and optionally **Fit seeds**. Original or D2 detection supports Peaks, Dips or Both and retains the loose pool as thresholds change. Candidate widths and spacing use source X units; maximum count zero is unlimited. **Seeds and fit results…** supports manual acceptance, position, amplitude, width, gamma and center constraints. Fits use Gaussian **sigma**, Lorentzian **HWHM**, or true Voigt **sigma and gamma**, with a constant baseline. The source/column labels and scientific **All / Common / Manual X** interval are shown above the controls. Toolbar pan/zoom does not alter that interval. Computations use unnormalized source values, never display offsets. X must be strictly monotonic across finite pairs; descending copies are reversed, irregular spacing is supported, and duplicate/nonmonotonic sweeps need an explicitly chosen monotonic source. Missing rows split detection spans; fitting uses all finite pairs in the selected interval. Detection and fitting run in the shared background queue and use the global **Cancel** command. Source or interval changes retire incompatible progress; seed and fit-setting changes retire affected fits, and obsolete job completions are ignored.

Detected crosses and the dashed fit overlay use the captured source curve’s normalization reference and full list/stack offset, including hidden preceding curves. Appearance changes redraw a valid result. Analysis overlays are **preview only** and are excluded from graph SVG/PNG/clipboard exports. **Save results to Workbook** creates detached **Detected peaks**, **Fit parameters**, and **Fit curves** or **Peak curves** Sheets as available, with raw quantitative values, model-width labels, baseline, RMSE, R² and captured source/interval/settings provenance. **Create analysis graph** saves and opens an ordinary editable Workspace graph. After **Find candidates**, it contains source data and separate **Peaks**/**Dips** marker curves; fitting is optional. When a completed fit is available, it contains source data, total fit, and each component plus baseline. Its SVG/PNG/clipboard exports include all these curves. Generated graphs start with no normalization, stacking or offsets; source values and missing-data gaps are retained. Save and Create reuse the same detached result Workbook; repeated Create reopens the graph and preserves its styles. Removing the generated graph or result records allows recreation. Changed results produce a new snapshot. **Save Project** also retains the comparison's selected curve, input identity, settings, candidate pool, filters, manual seeds, fits and status independently of these exports. Reopening restores compatible progress after checking the source values and interval. Detached result snapshots survive source removal. No-seed results have no Fit, Save or Create action.


Use **Project → Import** or **File → Import data…** for automatic numeric import. Content determines the type: complete Gate headers, embedded Gate layouts or the supported numeric Gate row identify a matrix; ordinary and headerless tables default to XY even with a DAT suffix. XY tables keep row order, every column and missing values; matrices keep every Gate with the existing sorted Gate coordinates and interpreted spectral X axis. The first-X/all-Y column roles do not alone identify a heatmap: matrix analysis also requires its Gate coordinates and intensity grid. The default creates one filename-named Workbook per file with an **Original** Sheet and opens only the first affected Workbook; other imported Workbooks remain in Project, and existing windows stay open. Source reuse preserves its original type, values, X/Y mapping, Sheet identity and Workbook even if its file has changed or disappeared.

For optional review, choose **Import with options…**. The preview explains the detected type and allows corrections; its destination menu also offers one new Workbook or an existing Workbook for intentional grouping. Choose **Import only**, **Import and compare** for a new graph, or a named comparison and **Add to comparison**. Gate/Y selections choose comparison curves and column roles; they never discard unselected matrix Gates or table columns. A graph's **Add data…** menu offers **Existing Sheets…** and **From files…**; From files always reviews the curve selection before adding to that graph. Matrix Sheets retain access to the existing scientific analysis by selecting a Gate.

Double-click a Sheet in the navigator to open its workbook tab. Tables are read-only. Select cells, row headers or column headers and press **Ctrl+C** for tab-separated values with full numeric precision. Use the shared **Line**, **Scatter**, **Line + Symbol**, **Heatmap**, and **Add to…** icon toolbar above Workspace. Column headers choose Y columns with Ctrl/Shift; right-click a header for the same plot commands or **Set as X**. Without a new column selection, plotting uses the Sheet’s retained X/Y mapping (first X and all remaining Ys on import). Cell and row selections remain copy selections and never slice a plot. **Add to…** names its target beside the button. Choose **Pin target** to keep that destination while visiting other graphs, importing files or switching Sheets. An explicit target choice replaces the pinned destination. Appending keeps the source active; **Show target** opens the destination. Closing or renaming a target preserves its identity; removing it clears the destination until another is chosen. **Target…**, Pin target and Show target remain available through native toolbar overflow. Pinning lasts for the current project session and clears on New/Open. Every curve retains its own X grid; files of different lengths are neither resampled nor sorted.

New curve legends include the source filename (or Workbook for embedded values), Y column or actual DAT Gate value, and result/Sheet context where needed. Matching filenames use a folder qualifier. Existing and customized legends stay unchanged. Additions skip an exact source Sheet + X column + Y column + values match by default, including hidden curves; the status bar reports added and skipped counts without a duplicate dialog. Use **Add again** in the Workbook Add menu, **Add current DAT Gate again** in Project Actions, or **Include existing curves (add again)** in either import/Sheet dialog for intentional copies. Different result Sheets, snapshots and column mappings remain separate curves.

**Project → Actions → Compare selected data…** expands selected Workbooks to all their Original Sheets, including multiple sources in a merged Workbook. Explicit Sheet selections also include result Sheets. The review dialog uses the same Workbook default; result checkboxes remain available individually. For DAT Original/Processed sources, select the desired Gate columns and choose **Match selected Gates** to apply their physical values to checked DAT Original/Processed Sheets. Each source resolves its own column indices. A missing or ambiguous exact value names the source and Gate and leaves every choice unchanged. XY and non-Gate result mappings stay independent; opening or checking a source never matches Gates automatically.

DAT processing remains available from the source data workflow. The Analysis workbench has its own explicit bound input and exposes **Edit source format** for source changes. Applying source processing does not silently replace retained Analysis input; use **Use input** to capture it deliberately.

Each imported spectrum DAT has an **Original** Sheet showing imported values in sorted analysis-axis order. **Processed** appears after applied processing, independently of pending controls. Selecting a Gate column updates the scientific Gate selection while keeping the Workbook visible. The active Gate header is marked with an arrow. **Add current DAT Gate to comparison** adds the current applied trace, and processed curves refresh after processing.

Importing, processing or saving a new DAT does not create a heatmap document. **Heatmap**, **View → Open Graph**, and **New Graph** create ordinary source graphs. **Analyze** creates or reuses its associated result graph and opens the shared editor. Closing a view retains the document for reopening.

**Heatmap** is available for DAT **Original** and **Processed** Sheets. The source binding survives closing/reopening, project save/load, plot-sidecar recall, and SVG/PNG export. Automatic colors use the selected samples, and Original graphs keep raw signal labels even while processed data exists. Ordinary XY tables have no physical Gate coordinates, so their Heatmap command is disabled with an explanation. Source arrays and Sheet contents remain unchanged.

**Export linecut graph** explicitly creates a detached Workspace XY graph for the current Gate detection or fit. This is an optional secondary output. Find, Filter, Fit and Gate navigation reuse the existing Analysis Graph and create no additional windows.

The DAT **Results table** shows each Gate's status, accepted seed positions and participating fitted centers and widths. Accepted seeds outside the fit interval remain listed with empty fit fields. **Save snapshot…** on a Workbook captures independent values, mapping and provenance; snapshots survive processing and removal of the source DAT. The comparison toolbar provides Home, Back, Forward, Pan and Zoom. **Inspector** shows or hides Properties without changing selection, unfinished edits or the graph. Graph name changes only the navigator/window name and does not redraw the figure. The shared **Curve style:** commands apply Line, Scatter or Line + Symbol to selected curves in this graph. SVG and PNG exports use the same curve renderer as the preview and preserve gaps at nonfinite values. Use **Project → Actions → Open / Rename / Remove** (also on the tree context menu) for retained workbooks, ordinary Sheets and comparisons, or **New comparison graph** to begin with an empty graph. Removing a Sheet or workbook also removes its dependent curves; removing a DAT uses the established imported-dataset action. Source files are unchanged. Workbooks, comparisons and heatmaps share Free Windows, Tabbed View, Tile and Cascade. Closing a view retains its contents for reopening.

**Save Project** embeds numeric arrays, mappings, curve styles and document layout in the project. XY-only and mixed projects reopen even when their original files are unavailable; earlier project versions remain readable. File-menu Save/Open, recent projects, dropped projects, and Save before New/Open/Close run project archive work in the background. Save captures current editors and independent array copies first; edits made while saving remain unsaved. **Cancel operation** preserves the current workspace and an existing project file until atomic replacement succeeds. A cancellation received after replacement reports the successful save and cancels the pending project transition. Opening keeps the current workspace until reading and validation succeed.

**Edit → Undo / Redo** follows the active XY graph as well as DAT graphs. XY history restores curve edits, removal, order and selection, keeps up to 100 operations per graph during the session, and is omitted from saved projects.

Dense XY previews use bounded samples while scientific analysis and SVG/PNG exports retain full source resolution and missing-data gaps. Fitting scales its calculations for small or large signal units and returns parameters in source units; a constant trace has undefined R². Derivative processing and fit evaluation check cancellation during calculations, and repeated requests retain only the newest pending operation.

## DAT format expected
- Header row with gate values is supported, e.g.:
  - `Photon energy(eV)    -1.0    -0.5    0.0 ...`
- Data rows:
  - first column: energy
  - remaining columns: intensity vs gate

The app also handles common whitespace/comma/tab separated numeric rows.
